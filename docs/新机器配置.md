# Second Brain：在新机器上安装和使用 vault

> 适用于：在另一台电脑上**使用** Second Brain vault（ingest 资料、审阅 plan、阅读 wiki）。
> 不包括 second-brain 项目本身的开发；vault 的升级见第 8 节。最后更新：2026-09-24（second-brain v0.1.0）。

## 1. 先弄清楚：vault 是自包含的

vault 目录里已经包含了使用所需的全部东西：

```text
second-brain-vault\
├─ tools\second_brain.py   工具（discover、render-plan、apply-plan、maintain……）
├─ tools\agent_guard.py    防止 agent 直接写 wiki 的 hook
├─ AGENTS.md、INGEST.md、PLAN-SCHEMA.md、README.md    agent 规则和使用说明
├─ .claude\、.codex\、.github\、.vscode\              各 agent 的权限和 hook 配置
├─ raw\     资料      wiki\   知识      plans\   plan      state\   记录（不能丢）
```

所以日常使用时**不需要** second-brain 项目，运行时不依赖它；只有新建 vault（第 3 节情况 B）和升级（第 8 节）时才用到它。

## 2. 需要安装的软件

| 软件 | 用途 | 检查命令 |
|---|---|---|
| Python 3.10 以上（只用标准库，不需要 pip 安装任何包） | 运行 vault 中的工具 | `python --version` |
| Claude Code（推荐）；或者 Codex、VS Code + GitHub Copilot | 做 ingest 的 agent | `claude --version` |
| Obsidian（可选） | 阅读和手工编辑 wiki | — |
| Git（情况 B 和升级时需要，也可以改为下载 ZIP） | 获取 second-brain 项目 | `git --version` |

## 3. 得到 vault：两种情况，选一种

### 情况 A：搬迁已有的 vault（继续使用原来的知识库）

1. **在旧机器上**确认 vault 处于干净状态，再复制：
   ```powershell
   cd <旧机器上的>\second-brain-vault
   python tools\second_brain.py status      # 应该是 incomplete transactions: none，lock: free
   ```
   如果有未完成的事务，先在旧机器上处理完（按 status 的提示运行 `rollback`）。
2. 复制**整个** `second-brain-vault\` 目录，放到新机器的任意位置，包括 `raw\`、`wiki\`、`plans\`、`state\`
   以及以 `.` 开头的隐藏目录（`.claude\`、`.codex\`、`.github\`、`.vscode\`），不要漏掉。
   `state\` 中是 registry、baseline 和事务记录，少了它 vault 就无法使用。
3. 两台机器不要同时修改同一个 vault。搬迁之后只在一台机器上使用它，或者每次用完再整体复制回去。

> ⚠ `raw\` 和 `wiki\` 中是你的资料和知识。如果其中有工作资料，复制时遵守所在组织的规定（例如只用批准的网盘或
> 加密 U 盘）；不要把 vault 放进公开的 GitHub repo。

### 情况 B：新建一个空 vault

```powershell
cd <任意工作目录>
git clone https://github.com/huigangz/second-brain.git
#   不用 git 也可以：在 https://github.com/huigangz/second-brain 下载 ZIP 并解压，文件夹改名为 second-brain
cd second-brain
python tools\second_brain.py install ..\second-brain-vault   # 目标目录必须还不存在，install 会创建它
```

装好以后，`second-brain` 这个目录只有升级时才用得到（第 8 节）。可以保留，以后用 `git pull` 更新；也可以删掉，需要升级时再重新 clone。

## 4. 验证 vault

```powershell
cd <路径>\second-brain-vault
python tools\second_brain.py status      # 列出 sources；incomplete transactions: none；lock: free
python tools\second_brain.py maintain    # 应该输出 no issues
```

## 5. Agent 设置

**Claude Code（推荐）**
1. 在 vault 目录中**交互式地**启动一次，并接受 trust 对话框（不接受的话，agent 连 plan 都写不了）：
   ```powershell
   cd <路径>\second-brain-vault
   claude
   ```
2. 第一次使用时做冒烟测试，让 agent 分别尝试：
   1. 直接编辑 `wiki/index.md` → 应该被拒绝；
   2. 运行 `apply-plan` → 应该弹出确认框（这次选择拒绝）；
   3. 写 `plans/pending/test.json` → 应该被允许（测试完删掉这个文件）。

**Codex（如果使用）**
- 用户级配置 `~/.codex/config.toml` 中如果有 `approvals_reviewer = "guardian_subagent"`，改为 `"user"`。
- 已知限制：Codex 可能绕过限制直接写 wiki。每次用完运行 `maintain`；发现自己没改过的 `HUMAN_EDITED`
  页面，用 `maintain --revert <page_id>` 恢复。

**GitHub Copilot（VS Code，如果使用）**
- 在 VS Code 中打开 vault 目录，并信任工作区（Workspace Trust）。

## 6. Obsidian（可选）

- 用 Obsidian 打开 vault 目录（Open folder as vault）。
- Settings → Files and links → Excluded files：加入 `state/`、`plans/`、`tools/`、`output/`。

## 7. 日常使用（简要）

```powershell
# 加资料：把文件放进 raw\documents、raw\meetings 或 raw\sessions，然后
python tools\second_brain.py discover
python tools\second_brain.py status

#   （discover 也可以让 agent 运行：它会弹出确认框，你确认后才执行）

# ingest：在 Claude Code 中说  ingest <source_id>
# agent 写好 plan 后，由你审阅并执行（也可以对 agent 说"执行这个 plan"，
# 它会弹出确认框：核对框中的 sha 与你审阅的 render 一致再确认）：
python tools\second_brain.py render-plan plans\pending\<plan_id>.json      # 看第一行的 PLAN SHA256 和 diff
python tools\second_brain.py apply-plan  plans\pending\<plan_id>.json --approve <PLAN SHA256>
#   或者打回：python tools\second_brain.py reject-plan plans\pending\<plan_id>.json --reason "…"

# 定期检查
python tools\second_brain.py maintain
```

完整说明见 vault 中的 `README.md`（中英双语）。

## 8. 升级 vault（项目有新版本时）

`upgrade` 要从 second-brain 项目中运行，项目放在哪里都可以，vault 的路径作为参数传入。

```powershell
# 1. 拿到最新的项目：保留了 clone 的话，更新它
cd <路径>\second-brain
git pull
#    之前删掉了的话，重新 clone（或者下载 ZIP）
git clone https://github.com/huigangz/second-brain.git

# 2. 先预览，再执行（执行前关掉 vault 里正在运行的 agent session）
python tools\second_brain.py upgrade <路径>\second-brain-vault --dry-run
python tools\second_brain.py upgrade <路径>\second-brain-vault

# 3. 验证
cd <路径>\second-brain-vault
python tools\second_brain.py maintain      # no issues
```

- upgrade 只更新规则和工具文件，不动 `raw\`、`wiki\`、`plans\`；`state\` 中只重写 `kit.json` 并追加一条事件。
- 报 `KIT_CONFLICT`：这台机器上有人改过 vault 中的规则或工具文件。需要保留，就先把改动做进你所用的项目副本的
  `vault-template\`，再 upgrade；不需要保留，就加 `--force`。
- 报锁被占用：有命令正在运行（通常是 agent），等它结束再运行。
- 想固定在某个发布版本：在项目中先 `git checkout v0.1.0`，再运行 upgrade。
- 从另一台机器复制过来的 vault 带有 `state\kit.json`，可以直接 upgrade，不会误报 CONFLICT。

## 9. 常见问题

| 现象 | 原因和处理 |
|---|---|
| `python` 不是可识别的命令 | 安装 Python 时没有勾选 "Add python.exe to PATH"。重新安装并勾选，或者用 `py` 代替 `python` |
| Claude Code 中 agent 连 plan 都写不了 | 没有接受 trust 对话框，见第 5 节 |
| `status` 显示未完成的事务 | 按提示运行 `rollback <txn_id>`；如果 rollback 中断了，再运行一次同一条命令 |
| `status` 提示锁被占用，但确认没有其他命令在运行 | `python tools\second_brain.py unlock --force` |
| 复制过来后 `maintain` 报了很多问题 | 多半是复制时漏了文件（特别是 `state\` 或隐藏目录）。重新完整复制 |
| `install` 报 `already exists` | 目标目录已经存在。install 只会新建目录，换一个还不存在的路径 |
